# 16 — 从零实现你自己的脚本引擎（终篇：综合路线图）

**难度：★★★★★　前置：全部前 15 篇**

前 15 篇拆解了 AngelScript 的每个器官；这一篇把它们重新组装：如果今天从一张白纸开始写一个"嵌入式、静态类型、可与 C++ 双向绑定"的脚本引擎，应该按什么顺序做、每一步的最小可行方案是什么、AngelScript 在哪些岔路口做了什么选择。**建议真的动手做——哪怕只完成里程碑 M0-M3，对引擎源码的理解也会脱胎换骨。**

## 零、先做三个顶层决策（AngelScript 的答案供参照）

| 决策 | 选项 | AngelScript 的选择与理由 | 对应文档 |
|------|------|------------------------|---------|
| 类型模型 | 静态 vs 动态 | **静态**——嵌入宿主 C++ 时类型即契约，绑定零猜测、错误编译期暴露；代价是编译器复杂一个数量级（重载决议、隐式转换全在编译期） | 05、08 |
| 执行模型 | 树遍历 / 字节码栈机 / 寄存器机 / JIT | **字节码栈机**——实现简单、可序列化、可挂起；性能足够（游戏逻辑不是数值内核）。留有 JIT 接口但核心不依赖 | 09、11 |
| 内存模型 | 纯 GC / 纯引用计数 / 混合 | **引用计数为主 + 循环检测 GC 兜底**——确定性析构对游戏资源至关重要，GC 只处理循环 | 14 |

写自己的引擎时，每个决策都可以选更简单的分支（动态类型 + 树遍历 + 纯引用计数），先跑起来再演进。

## 一、里程碑拆解（每步都有可运行的产出）

### M0：管道骨架（1-2 天）

**产出**：`run("print(42)")` 能打印 42。

- 词法器：手写状态机，先只支持整数、标识符、单字符运算符（→ 03 篇的 GetToken 主流程，跳过所有字面量花活）；
- 语法器：递归下降，只支持"表达式语句 + 函数调用"（→ 04 篇；节点用 first-child/next-sibling，一个 struct 走天下）；
- 不生成字节码，先**树遍历求值**——让管道先通，M2 再换栈机；
- 绑定：一个 `map<string, void(*)(vector<Value>&)>` 的函数表——这其实就是 13 篇 generic 约定的原始形态。

> AngelScript 对照：它从一开始就是字节码 + 静态类型，所以没有这个阶段。但你读 as_tokenizer.cpp 会发现它的词法器也不过是放大号的手写状态机。

### M1：表达式与静态类型（3-5 天）

**产出**：`int a = 1 + 2 * 3; print(a)`，类型错误能报编译错。

- 引入 `DataType` 值对象（→ 05 篇 asCDataType：基础类型枚举 + 修饰位，不要用字符串比类型）；
- 表达式编译带类型标注：每个子表达式返回 `(类型, 值/代码)` 对——这是 08 篇 asCExprContext 的最小版，**理解了它就理解了 as_compiler.cpp 的一半**；
- 运算符类型检查 + 最简隐式转换（int→float 一条就够）；
- 变量：符号表 + 作用域栈（→ as_variablescope.cpp）。

### M2：换装字节码栈机（3-5 天）

**产出**：同 M1 功能，但走 编译→字节码→VM 三段，支持 if/while。

- 指令集从 10 条起步：PUSH/POP/ADD/SUB/MUL/CMP/JMP/JZ/CALLSYS/RET（→ 09 篇；定长编码，一条指令 = opcode + 一个操作数，够用很久）；
- VM：`while(true) switch(*pc++)` 大循环 + 操作数栈（→ 11 篇；**栈用自己 new 的内存块，不要用 C++ 递归**——这是日后能做协程的前提）；
- 控制流：编译 if/while 时的标签回填（→ 08 篇控制流一节）；
- 加一条 SUSPEND 指令 + 行号表——调试与超时的地基几乎免费。

### M3：函数与调用栈（3-5 天）

**产出**：脚本能定义函数、递归调用；宿主能按名调脚本函数。

- 两遍编译登场：第一遍收集全部函数签名，第二遍编函数体——否则前向引用/递归无法处理（→ 07 篇，这是 as_builder.cpp 存在的全部理由）；
- CALL/RET 指令与栈帧（返回地址 + 帧基指针压栈，→ 11 篇 CallScriptFunction 走读）；
- 宿主 API 定型：engine（注册+编译）/ module（产物容器）/ context（执行栈）三对象分离（→ 06、10 篇。这个切分是 AngelScript API 耐用 20 年的原因，抄它）。

### M4：对象与生命周期（1-2 周，第一道大坎）

**产出**：注册 C++ 类给脚本用（引用类型 + 引用计数）；字符串类型。

- 引用类型协议：类型注册表 + ADDREF/RELEASE 行为（→ 06 篇注册校验、12 篇对象模型）；
- 编译器开始管对象生命周期：临时对象何时释放、赋值语义（→ 08 篇最难的部分，先只支持句柄赋值可以绕开大半）；
- 字符串：作为注册的对象类型而非内建（→ AngelScript 的字符串工厂设计，asbuild 示例 README 有详解）；
- **此阶段建议只做 generic 调用约定**——宿主函数一律 `void f(MyGeneric*)` 包装，零汇编、全平台（→ 13 篇的忠告）。

### M5：脚本类（1-2 周）

**产出**：脚本里 `class C { int x; void f(){} }`，宿主能创建实例、调方法。

- 实例 = 头部（refcount + 类型指针）+ 属性区，偏移编译期算好（→ 12 篇内存布局）；
- 编译器合成工厂函数与构造/析构（→ 12 篇对象诞生记）；
- 先不做继承；加接口（纯签名检查 + 方法表映射）比加继承便宜且实用（→ game 示例的 IController 模式）。

### M6：循环检测 GC（3-5 天）

**产出**：`class Link { Link@ next; }` 自环不泄漏。

- 试删除法：候选集合 → 计数器清零 → 枚举内部引用 +1 → 计数相等者疑似死环 → 验证 → 打破（→ 14 篇状态机走读，算法本体不到 300 行）；
- 对象协议加三件套：枚举引用/释放引用/GC 标志。

### M7+：选修进阶（每项都是独立课题）

| 课题 | 参照 | 备注 |
|------|------|------|
| 原生调用约定（脱离 generic） | 13 篇 + as_callfunc_x64_msvc_asm.asm | 只做自己平台的一种 ABI；用 test_feature 的思路建回归 |
| 字节码序列化 | 15 篇 | 指针→索引重写是唯一难点 |
| 协程/挂起 | 11 篇 + samples/events·coroutine | 栈是堆内存块的话，几乎免费 |
| 重载决议 + 完整隐式转换 | 08 篇 | 成本分级表直接抄 |
| 窥孔优化 | 09 篇 | 收益/复杂度比最高的优化 |
| 继承/虚表、模板容器、闭包/委托 | 12、06 篇 | AngelScript 也是演进多年才齐 |

## 二、AngelScript 教给实现者的十条经验

1. **声明字符串复用 parser**（06 篇）——注册 API 的声明解析与脚本编译共用一个前端，一份语法两处受益。
2. **单一 AST 节点类型**（04 篇）——枚举 + 孩子链，比继承体系省一半代码，序列化/池化都容易。
3. **表达式 IR = 类型 + 字节码片段随身带**（08 篇）——不建独立 IR 层，递归下降现场拼接，单遍出码。
4. **栈内存与 C++ 栈解耦**（11 篇）——挂起、协程、超时、深递归全部由此解锁，是嵌入式引擎最划算的一个决定。
5. **机制在引擎、策略在宿主**——引擎只给可挂起的 VM，调度器（contextmgr）、调试器（debugger）全是 add_on 用公开 API 搭的。API 完备性 > 功能内置。
6. **引用计数为主、GC 为辅**（14 篇）——确定性析构 + 循环兜底，两全。
7. **generic 调用约定永远保留**（13 篇）——原生 ABI 桥是移植成本的大头，可移植兜底让引擎"到处能跑"。
8. **行号指令是一等公民**（09、11 篇）——调试、超时、性能采样、协程切换共用一个 SUSPEND 挂点。
9. **错误文本集中一处**（as_texts.h）——本地化、grep 定位、文案一致性三得。
10. **回归测试按特性一文件**（tests/test_feature）——每修一个 bug 加一个测试置顶，20 年积累出 170+ 文件的安全网。

## 三、检验清单

完成 M0-M6 后，用这些问题自测对 AngelScript 的理解（都能在前 15 篇找到答案）：

- [ ] `a + b` 从 AST 到字节码到 VM 执行，完整路径能在纸上画出来吗？
- [ ] 为什么 Suspend 不需要保存 C++ 调用栈？
- [ ] 引用类型按值传给脚本函数时，谁在何时 AddRef/Release？
- [ ] 字节码文件里为什么没有指针却能跨平台加载？
- [ ] 循环引用检测为什么需要"验证"阶段（直接销毁疑似对象会出什么错）？
- [ ] 注册一个缺 RELEASE 行为的引用类型，引擎在哪一步、以什么错误拒绝？
